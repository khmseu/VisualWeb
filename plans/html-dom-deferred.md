# HTML/DOM Deferred Features

This is the revisit-ready backlog for HTML/DOM work postponed by the
[prioritized support roadmap](whatwg-html-dom-completion-roadmap.md). These are
not permanent exclusions. Reclassify an item when a common-site requirement
needs it, a dependency becomes available, or implementation cost falls.

The initial list was checked against the current subsystem guides, standards
inventory, `plans/Missing.md`, implementation markers, and focused tests. It is
not an exhaustive audit; Phase 1 may still refine each item's exact algorithm
scope. HTML/DOM estimates remain rough heuristics, not conformance scores.

## Phase 1 audit evidence

- **HDF-001:** The [HTML/DOM guide](../docs/html-dom.md#dom-boundary-and-invariants)
  defers shadow DOM and most special-element behavior.
  [DomBindings.cs](../src/Engine/Engine.Scripting/DomBindings.cs) explicitly
  defers custom-element options; the existing DOM and scripting test projects
  contain no shadow-tree or custom-element suite.
- **HDF-002:** [DomNode.cs](../src/Engine/Engine.Dom/DomNode.cs),
  [DomCharacterData.cs](../src/Engine/Engine.Dom/DomCharacterData.cs), and
  normalization document observer/live-range reactions as deferred. Existing
  CharacterData, normalization, and tree-inspection tests cover adjacent
  primitives, not MutationObserver or Range APIs.
- **HDF-003:** The [scripting guide](../docs/scripting.md) describes bounded
  bindings and defers general Web IDL. Existing scripting tests cover selected
  interfaces and conversion behavior, not generated interface-wide bindings.
- **HDF-004:** The HTML guide and `Engine.Html` README state that frames do not
  create browsing contexts or load resources. [TreeTests.cs](../tests/Engine.Html.Tests/TreeTests.cs)
  cover static frameset parsing, not nested navigation or frame lifecycle.
- **HDF-005:** [HtmlParser.cs](../src/Engine/Engine.Html/HtmlParser.cs)
  explicitly rejects `svg` and `math`; tree and fragment tests verify explicit
  unsupported failures. [DomElement.cs](../src/Engine/Engine.Dom/DomElement.cs)
  hardcodes `NamespaceUri` to the HTML namespace, and its attributes have no
  namespace identity. A parser-only increment would therefore produce
  incorrect foreign trees; namespace-aware parsing and DOM support are deferred.
- **HDF-006/HDF-007:** Canvas and media are listed among later browser
  capabilities in the [approved foundation roadmap](browser-foundation-plan.md)
  and have no corresponding implemented engine project/test suite.
- **HDF-008:** The [networking guide](../docs/networking.md) and
  `plans/Missing.md` describe the loader as a bounded privileged subset, not
  full Fetch/CSP. Existing network/browser tests exercise selected policies
  only.
- **HDF-009:** The [project map](../docs/project-map.md) and approved foundation
  roadmap defer workers and storage; no worker/storage engine or test suite is
  present.
- **HDF-010:** [InlineScriptTests.cs](../tests/VisualWeb.Browser.Tests/InlineScriptTests.cs)
  verifies parser-pausing external classics and explicit scheduling rejection;
  [ModuleExecutionTests.cs](../tests/Engine.Scripting.Tests/ModuleExecutionTests.cs)
  verifies imports fail without a loader. The current source broker is a
  parser-pause request/response path, so external async/defer requires a
  different bounded scheduling design; the inline classic no-op attributes do
  not add asynchronous fetching.
- **HDF-011:** `HtmlParser` retains explicit unsupported paths for remaining
  tree-construction algorithms: the table-mode default foster-parent path
  throws for unhandled content and some foster insertion locations are
  unsupported. [Full completion plan](html-dom-full-completion-plan.md) Phase 1
  is in progress; this increment has no new subsystem dependencies. The adoption
  form-removal guards cannot be reached with the
  current HTML-only stack: `form` is special, so the first such form is the
  furthest block, not a node popped in the no-block or inner-loop branches.
  `AdoptionWithFormAsFurthestBlockKeepsFormPointerUntilEndTag` tests that
  adoption retains the pointer. `TableTextAfterTemplateInOpenStackFostersIntoTemplateContent`,
  `TableTextFostersIntoTemplateWhenNoTableIsOpen` and
  `TableFragmentFostersTextIntoLastOpenTemplateAndHonorsLimits` cover the
  adjacent table-text fix, including text merging, fragment ownership and limits.
  `FosteredTableTextUsesOpenStackParentAfterScriptDetachesTable` covers the
  previously unsupported table-text location when a parser callback removes the
  last open table; `FosteredTableTextUsesMovedTableParentRatherThanOpenStackParent`
  preserves the parented-table path. `FosteredTableTextIsDiscardedWhenCallbackMovesTableToDocument`
  covers the document-parent case, where the character insertion algorithm
  discards text without allocating a node, and checks cancellation.
  `FosteredDetachedTableTextHonorsNodeLimitAndCancellation`
  covers the detached-table limits and cancellation, while
  `TableFragmentFosteredTextAppendsAtSyntheticRoot` checks the separate
  no-open-table fragment location. Other foster insertion failures remain
  explicit.
  `SelectIgnoresTableStructureStartAndKeepsOptionContent` and
  `SelectContextIgnoresTableStructureStart` cover in-body ignored
  table-structure starts inside selects and select fragments;
  `SelectTableStructureStartRecoveryHonorsLimitsAndCancellation` checks
  node/error budgets and cancellation. `SelectIgnoresUnmatchedTableStructureEnd`
  and `SelectContextIgnoresUnmatchedTableStructureEnd` cover generic in-body
  recovery for unmatched structure end tags; `SelectInCellPreservesCellEndTagRecovery`
  preserves the distinct in-cell closing behavior.
  `EarlyTableStructureTagsRecoverThroughDocumentModes` covers structure starts
  and ends across early document modes, with
  `TableStructureEndInHeadDoesNotCloseHead` and
  `EarlyTableStructureRecoveryHonorsLimitsAndCancellation` covering head
  preservation and parser budgets.
  `TableStructureTagsInHeadNoscriptFollowTheirDistinctRecoveryRules` and
  `TableStartInHeadNoscriptIsReprocessedInBody` cover the head-noscript
  recovery path; table end, scripting-enabled raw text, budgets and
  cancellation are separately tested.
  Fragment contexts `svg`, `math`, `frame`, and `frameset` are explicitly
  rejected. [TreeTests.cs](../tests/Engine.Html.Tests/TreeTests.cs) includes
  `UnsupportedTableRecoveryFailsExplicitly` and
  `UnsupportedTreeAlgorithmsFailExplicitly`; remaining work must still map each
  common parser failure to the pinned fixture family or a focused test.
- **HDF-012:** Platform accessibility integration is outside the HTML/DOM
  implementation boundary in the [architecture guide](../docs/architecture/overview.md);
  it remains related work, not a claim about a missing DOM node algorithm.
- **HDF-013:** The [browser-shell guide](../docs/browser-shell.md) describes
  shell-owned form editing/submission and the bounded type=button click path;
  [ButtonClickEventTests.cs](../tests/VisualWeb.Browser.Tests/ButtonClickEventTests.cs)
  covers the latter in local and process modes. Submit/reset click defaults and
  input/change/submit/reset events remain unsupported. The browser's current
  values are not live renderer DOM state, and an event listener may mutate form
  ownership or controls before a retained repaint. Reusing an old control index
  after that repaint could submit or reset the wrong state; implement only with
  an explicit identity/value reconciliation design.
- **HDF-014:** [Text and layout](../docs/text-layout.md) and
  [HiddenRenderingTests.cs](../tests/VisualWeb.Browser.Tests/HiddenRenderingTests.cs)
  establish the current fail-closed behavior for visible
  `hidden=until-found`; script reflection does not trigger reveal.
- **HDF-015:** [The scripting guide](../docs/scripting.md#bounded-element-innerhtml)
  exposes only bounded `innerHTML`.
  [HtmlFragmentSerializer.cs](../src/Engine/Engine.Html/HtmlFragmentSerializer.cs)
  and [InnerHtmlTests.cs](../tests/Engine.Scripting.Tests/InnerHtmlTests.cs)
  cover element-context serialization/parsing and atomic child replacement,
  not parent-context sibling insertion or outerHTML replacement.

## Register maintenance

For each entry, keep the current support evidence and the exact missing behavior
specific. When work starts, record its roadmap phase and dependencies. When it
is implemented, remove or mark the item complete and link the tests/docs that
establish the result. If it is intentionally dropped, preserve that decision
and rationale rather than deleting the history.
